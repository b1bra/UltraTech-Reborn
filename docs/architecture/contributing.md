### Development Guidelines



#### *Branch Rules*



###### **main:**

Stable version of the project.



###### **development:**

Active development branch for current work.



#### Commit Rules



###### Commits should:

\- Describe the actual change.

\- Be small and focused.

\- Avoid combining unrelated changes.



##### Examples:



###### Good:

add mod analysis documentation



###### Good:

fix recipe restoration system



###### Bad:

update files





##### Code Changes



\- Document major changes.

\- Avoid modifying original mod code directly when possible.

\- Prefer separate patches or compatibility systems.

\- Test changes before merging.





##### Documentation



Every major change should include:

\- Description of the change.

\- Reason for the change.

\- Testing information.
